## 1. 目的

ローカルPC上の LLM（Ollama）を使ったチャットアプリを、Docker Compose で構築する。
画面からモデルを選び、ダウンロード・削除・切り替えを行いながらチャットできることを目指す。
重すぎるモデルを選んでも、Windows・Ubuntu に悪影響を出さずに回復できる構成にする。

## 2. 対象範囲

### 今回やること
- Ollama コンテナ（LLM 実行）
- フロントエンドコンテナ（チャット画面）
- モデルの選択・ダウンロード・削除
- セッション履歴のファイル保存（最新10件）
- 高負荷時の保護と自動復帰
- 画像の添付（画像に対応したモデルのみ）

### 今回やらないこと
- 画像・動画生成（ComfyUI 等は別プロジェクトとして後日追加）
- 音声・動画の添付（音声は Ollama の対応が試験的、動画は Ollama が非対応のため）
- セッション途中でのモデル切り替え
- 複数ユーザー対応・ログイン
- データベースの利用

### 将来の拡張を見越した配慮
- **[決定]** 画像・動画生成は ComfyUI 等の別コンテナを同じ Docker Compose に追加して連携する
- **[決定]** フロントエンドから各コンテナへの接続先は設定で指定し、後からコンテナを足しても既存部分を作り直さずに済む構成にする
- 注意：VRAM 8GB を Ollama と ComfyUI で取り合うため、連携時はモデルのアンロード制御が必要になる
- **[決定]** 完成後に「スマホなど他端末からのアクセス」「ホスティングサービスでの公開」へ拡張しやすい実装にする（今回は localhost 限定。詳細は 8 章）
- **[決定]** 後から「ライト/ダークの手動選択」「英語版・日本語版の切り替え」を足しやすい実装にする（今回はシステム設定に追従・日本語のみ。詳細は 8 章）

## 4. システム構成

```
[Windows ブラウザ] http://localhost:3000
        │
        ▼
┌──────────────────┐   HTTP   ┌──────────────────┐
│ frontend コンテナ │ ───────▶ │ ollama コンテナ    │
│ チャット画面        │ ◀─────── │ GPU 使用            │
│ セッション保存      │          │ モデル実行・DL・削除 │
└──────────────────┘          │ メモリ上限あり       │
        │                     └──────────────────┘
  ./data/sessions/                     │
                                volume（モデル保存）
```

- **[決定]** Docker Compose で 2 コンテナ構成（`ollama` / `frontend`）
- **[決定]** LLM 実行には Ollama を使う
- **[決定]** モデル切り替えは Ollama コンテナを作り直さず、リクエストごとにモデル名を指定して行う
- **[決定]** ダウンロード済みモデルは Docker volume に保存（コンテナ再作成でも再ダウンロード不要）
- **[決定]** ポートは `3000`

## 5. 設定ファイル

### `.env`
- **[決定]** デフォルトモデルを指定する：`DEFAULT_MODEL=gemma4:e4b`
- **[決定]** 起動時にデフォルトモデルが未ダウンロードなら自動でダウンロードする
- **[決定]** Ollama コンテナのメモリ上限・応答の打ち切り時間・コンテキスト長の上限も `.env` で設定できるようにする

### モデル候補一覧（`models.yaml`）
- **[決定]** 未ダウンロードのモデルも画面に並べるため、候補一覧を設定ファイルに記載する
  - 理由：Ollama は「まだ持っていないモデル」の一覧を返さないため
- 記載項目：候補のモデル名とおおよそのサイズ（負荷区分の判定に使う）、自動検索する「モデルの種類」（5 章「起動時のモデル自動検索」）
- **[決定]** 初期の候補：

| モデル名 | サイズ目安 | 負荷区分 | 備考 |
|---|---|---|---|
| `gemma4:e4b` | 約 6.6GB | ✅ 快適 | デフォルトモデル |
| `gemma4:12b` | 約 8GB | ⚠ 低速 | VRAM ぎりぎり |
| `gemma4:26b` | 約 16〜19GB | ⚠ 低速 | MoE 型（計算時は約 3.8B 分のみ使用）。大きさの割に速い |

- 候補にしないもの：`gemma4:31b`（約 20GB で対象外）、`-mlx` 付き（Mac 専用）、`-cloud` 付き（ローカル実行ではない）

### 起動時のモデル自動検索
- **[決定]** `models.yaml` に「気になるモデルの種類」（例：`gemma4`、`qwen3`、`llama3.1`）を書いておき、起動時にその種類について新しいサイズの版を探して一覧に追加する
- **[決定]** 公式サイト（`ollama.com/library/<種類>/tags`）のページから版の一覧を読み取り、各版の正確なサイズは Ollama のレジストリ（`registry.ollama.ai` のマニフェスト）から取得する
  - 背景：Ollama には「ダウンロード可能なモデルの全一覧」を返す公式 API がない。サイトの読み取りはサイトのデザイン変更で動かなくなる可能性がある
- **[決定]** `.env` のしきい値（7.2 の ❌ 対象外の境界）を超えるモデルは一覧に出さない
- **[決定]** 標準の版だけを並べる。除外するもの：`-mlx`（Mac 専用）、`-cloud`（クラウド版）、`-bf16` / `-q8_0` / `-it-*` などの量子化・派生版
- **[決定]** 検索結果は 1 日保存し、起動のたびには検索しない
- **[決定]** オフライン時や読み取り失敗時は、エラーを出さずに `models.yaml` に直接書いたモデルとダウンロード済みモデルだけで起動する

## 6. 機能要件

### 6.1 モデル一覧・選択

```
モデル: [ gemma4:e4b                 ▼ ]  [🗑]
         ├ gemma4:e4b       ✅ すぐ使える
         ├ gemma4:12b       ✅ すぐ使える ⚠ 遅くなります
         └ gemma4:26b       ⬇ 未ダウンロード ⚠ 遅くなります
```

- **[決定]** 画面のプルダウンでモデルを選ぶ
- **[決定]** プルダウンの横に「（！）」アイコンを置き、押すと次の説明を表示する：「一覧にないモデルを使いたいときは、`models.yaml` にモデルの種類を追記してください。次回の起動時に、このPCで使えるサイズのモデルを検索して一覧に追加します」
- **[決定]** ダウンロード済みモデルと未ダウンロードモデルの両方を一覧に表示
- **[決定]** ダウンロード済みモデルを選んだら、即チャット可能
- **[決定]** 起動直後は `.env` のデフォルトモデルが選択された状態
- **[決定]** モデルをサイズで 3 段階に分類する（7 章参照）。❌ 対象外のモデルは一覧に出さない。⚠ 低速のモデルには「遅くなります」と注記する

### 6.2 モデルのダウンロード

```
┌─────────────────────────────────────┐
│ gemma4:26b はダウンロードされていません   │
│ サイズ：約18GB  ⚠ 遅くなります           │
│                [キャンセル] [ダウンロード] │
└─────────────────────────────────────┘
          ↓
┌─────────────────────────────────────┐
│ ダウンロード中…                          │
│ ████████████░░░░░░  62%（11.2/18GB）   │
│                            [中止]       │
└─────────────────────────────────────┘
```

- **[決定]** 未ダウンロードのモデルを選ぶとダイアログを表示
- **[決定]** [ダウンロード] ボタンでダウンロード開始、進捗バーを表示
- **[決定]** 完了後はフロントエンドを再起動せず、モデル一覧を自動更新する
- **[決定]** ダウンロードは同時に 1 つまで
- **[決定]** ダウンロード中は [中止] 以外のすべての操作を禁止する
- **[決定]** ダウンロード前にディスクの空き容量を確認し、足りなければ開始しない
- **[決定]** ダウンロードはサーバー側で実行する。ブラウザを閉じても続行し、開き直すと進捗ダイアログを再表示する
- **[決定]** 完了後、ダウンロードしたモデルを選択状態にする
- **[決定]** 失敗時（回線切断・ディスク不足など）はエラー内容をダイアログに表示し、操作禁止を解除する

### 6.3 モデルの削除

```
┌─────────────────────────────────────┐
│ gemma4:12b を削除しますか？（約8GB解放）  │
│                   [キャンセル] [削除する] │
└─────────────────────────────────────┘
```

- **[決定]** ダウンロード済みモデルを選んでいるとき、削除ボタンを表示
- **[決定]** 削除ボタンは **ゴミ箱アイコン**
- **[決定]** 削除前に必ず確認ダイアログを出す
- **[決定]** 使用中のモデルを削除したら、デフォルトモデルに自動で切り替える
- **[決定]** デフォルトモデルは削除不可（ゴミ箱アイコンを無効化）

### 6.4 チャット

- **[決定]** 選んだモデルに質問を送り、応答を画面に表示する
- **[決定]** 1 セッション＝1 モデル。会話が始まったらモデルのプルダウンをロックする
- **[決定]** 別モデルを使うときは [新しいチャット] から始める
- **[決定]** 応答は 1 文字ずつ流れるように表示（ストリーミング）。理由：ローカル LLM は応答完了まで数秒〜数十秒かかるため、待ち時間の体感を減らす
- **[決定]** 応答中は送信ボタンを無効化し、[停止] ボタンを表示
- **[決定]** 応答が一定時間（例：3 分）来なければ打ち切り、メッセージを表示する

#### 応答の表示（GitHub の Markdown 表示と同等）
- **[決定]** 見出し・太字・リスト・表・引用・リンク・チェックボックスを、記号ではなく整形して表示（GitHub Flavored Markdown）
- **[決定]** コードブロックは言語ごとの色分け＋コピーボタン
- **[決定]** ` ```mermaid ` のコードブロックは図として描画する
- **[決定]** 応答の途中（ストリーミング中）は Mermaid のブロックをコードのまま表示し、そのブロックが閉じた時点で図に切り替える。理由：書きかけの図は描画エラーになるため
- **[決定]** Mermaid の記述に誤りがある場合は、エラーを出さずにコードのまま表示する
- **[決定]** 応答に含まれる HTML は実行しない（安全のため）

#### 思考過程の表示
- **[決定]** 思考過程を出力するモデル（Gemma 4 など）は、思考部分を `▶ 考え中…（クリックで展開）` と折りたたんで表示し、その下に回答を表示する
- **[決定]** 思考過程もセッションの JSON に保存し、過去セッションを開いたときも同じく折りたたみで表示する

#### 会話が長くなったとき
- **[決定]** 会話の量がコンテキスト長の上限に近づいたら「会話が長くなりました。新しいチャットをおすすめします」と警告を表示する。送信はそのまま可能

### 6.5 セッション履歴

```
┌──────────────┬──────────────────────────┐
│ [＋新しいチャット]│ モデル: gemma4:e4b 🔒      │
│              ├──────────────────────────┤
│ ▶ Dockerの質問  │ あなた: …                  │
│   翻訳テスト     │ AI   : …                  │
│   …（最大10件） ├──────────────────────────┤
│              │ [ 入力…            ] [送信] │
└──────────────┴──────────────────────────┘
```

- **[決定]** ブラウザを閉じても前回までのセッションを残す
- **[決定]** DB は使わず、ファイルで保存する
- **[決定]** 保存は最新 10 件まで。11 件目ができたら最も古いものを自動削除
- **[決定]** 過去セッションを開いたとき、そのモデルが削除済みなら **閲覧のみ**（入力欄を無効化し「このモデルは削除されています」と表示）
- **[決定]** セッション名は最初の質問の先頭 20 文字程度から自動生成
- **[決定]** 形式は 1 セッション＝1 JSON ファイル。理由：発言者・モデル名を確実に読み戻せる
- **[決定]** 保存先は `./data/sessions/`（Windows のエクスプローラーからも見られる）
- **[決定]** 画面左にセッション一覧を表示し、クリックで開く
- **[決定]** セッション一覧の各行にゴミ箱アイコンを置き、確認ダイアログの後に手動で削除できる

### 6.6 画像の添付

```
┌──────────────────────────────────────┐
│ [🖼 photo1.png ✕] [🖼 graph.jpg ✕]      │ ← 送信前のサムネイル
│ [📎] [ この画像を説明して…        ] [送信] │
└──────────────────────────────────────┘
```

- **[決定]** チャットに画像を添付して送れる
- **[決定]** 選んでいるモデルが画像に対応していないときは、添付ボタン（📎）を無効化する。対応しているかは Ollama のモデル情報（capabilities）で判定する
- **[決定]** 添付した画像もセッションと一緒に保存し、過去セッションを開いたときも表示する。セッションを削除したら画像も削除する

Claude の判断（修正可）：
- 添付方法：📎 ボタン、ドラッグ＆ドロップ、クリップボードからの貼り付けの 3 通り
- 形式：PNG / JPEG / WebP。1 枚 10MB まで、1 回の送信で 4 枚まで
- 保存先：`./data/sessions/<セッションID>/` に画像ファイルとして保存し、JSON からはファイル名で参照する（JSON を軽く保つため）
- 画像はコンテキスト長を多く使うため、6.4 の「会話が長くなったとき」の警告の計算に含める

## 7. 高負荷時の保護と復帰

目的：重いモデルを選んでも、影響を Ollama コンテナの中だけに閉じ込める。

### 7.1 保護の仕組み

| 層 | 仕組み | 効果 |
|---|---|---|
| ① WSL | `memory=32GB`（設定済み） | Windows 側は最低 32GB 残る。Windows が固まらない |
| ② コンテナ | Ollama コンテナにメモリ上限（例：24GB）を設定 | 超えたら Ollama コンテナの中のプロセス（多くはモデルの実行プロセス、場合によりコンテナ全体）だけが強制終了。Ubuntu 本体・フロントエンドは無事 |
| ③ 自動復帰 | `restart: unless-stopped` を設定 | 強制終了しても数秒で自動で起動し直す |
| ④ 画面 | 応答の打ち切り時間＋[停止] ボタン（6.4） | 画面が固まったまま待ち続けない |
| ⑤ 会話の長さ | コンテキスト長に上限を設定 | 長い会話でメモリが膨らみ続けるのを防ぐ |

- **[決定]** 上記 ①〜⑤ をすべて入れる
- GPU：VRAM 8GB を超えた分は Ollama が自動で CPU 側に回すため、GPU が原因で PC が落ちることは基本ない（遅くなるだけ）

### 7.2 負荷区分（事前排除）

| 区分 | 条件（目安） | 画面での扱い |
|---|---|---|
| ✅ 快適 | 約 7GB 以下（VRAM に収まる） | 普通に表示 |
| ⚠ 低速 | 約 7〜20GB（CPU に一部退避） | 表示するが「遅くなります」と注記 |
| ❌ 対象外 | 約 20GB 以上（コンテナ上限に近い） | **一覧に出さない** |

- **[決定]** 未ダウンロードのモデルは `models.yaml` のサイズ（自動検索分はレジストリのサイズ）で判定し、ダウンロード前に分かるようにする。ダウンロード済みのモデルは Ollama が返す実サイズで判定する（11 章の 4）
- **[決定]** しきい値（7GB / 20GB）は `.env` で変更できるようにする

### 7.3 強制終了時の扱い

- 制約：メモリ上限で強制終了されたとき、その質問への回答は失われる（途中まで届いた分は「（中断）」付きで残る）
- 起こり方は 2 通りある。(a) Ollama 本体は動いたまま、モデルの実行プロセスだけが落ちる／読み込みを拒否される、(b) Ollama コンテナごと落ちて自動で再起動する。どちらも同じ表示で扱う
- **[決定]** 画面に「モデルが重すぎて停止しました。再起動中です」と表示する
- **[決定]** Ollama の復帰を確認したら、表示を消して入力を再開できるようにする

## 8. 非機能要件

- **[決定]** Windows のブラウザから `http://localhost:3000` で利用できる
- **[決定]** `docker compose up -d` の 1 コマンドで起動できる（普段は 8.4 のスクリプトを使う）
- **[決定]** PC 再起動後も、モデルとセッション履歴が残っている

### 8.1 アクセス範囲と将来の公開
- **[決定]** 今回はこの PC からのみアクセス可能（ポートは `127.0.0.1` にだけ公開）。理由：ログイン機能がないため
- **[決定]** 将来の拡張（スマホ等からのアクセス、ホスティングサービスでの公開）に備え、以下の形で作る
  - 公開範囲（待ち受けアドレス・ポート）は `.env` で変更できる
  - 画面からの操作はすべてフロントエンドのサーバー処理（API）を経由し、ブラウザから Ollama を直接呼ばない。理由：後から認証を 1 か所に足せば済むようにするため
  - 認証を差し込む場所（Next.js の proxy。Next.js 15 以前の名前は middleware）を用意しておき、今回は「何もしない」実装にする

### 8.2 配色
- **[決定]** ライト/ダークは OS（Windows）の設定に自動で合わせる
- **[決定]** 将来の手動切り替えに備え、色はテーマ用の変数で一元管理し、「システム / ライト / ダーク」の 3 値を持てる設定の形にしておく（今回は「システム」固定・切り替え画面なし）

### 8.3 言語
- **[決定]** 今回は日本語のみ
- **[決定]** 将来の英語版追加に備え、画面の文言はコードに直接書かず、言語ごとの文言ファイル（例：`messages/ja.json`）から読む形にする

### 8.4 起動・終了スクリプト
- **[決定]** アプリの起動と終了を簡単にするスクリプトを用意する

| ファイル | 使う場所 | 動き |
|---|---|---|
| `scripts/start.sh` | WSL のターミナル | ① Docker が止まっていれば起動 → ② `scripts/up.sh`（専用ビルダーでビルドして `docker compose up -d`）→ ③ 画面が応答するまで待つ（最大 2 分、待ち中は進み具合を表示） → ④ Windows のブラウザで `http://localhost:3000` を自動で開く |
| `scripts/stop.sh` | WSL のターミナル | `docker compose down` でコンテナを止める。モデルとセッション履歴は消さない |
| `LocalLLM-start.bat` / `LocalLLM-stop.bat` | Windows のデスクトップ（ダブルクリック） | WSL 経由で上の `start.sh` / `stop.sh` を呼ぶ。`scripts/install-windows-shortcuts.sh` でデスクトップに生成する |

Claude の判断（修正可）：
- 起動に失敗したとき（Docker 未インストール、GPU が見えない、ポート 3000 が使用中など）は、原因と対処を 1 行ずつ表示して終了する
- すでに起動中に `start` を実行したら、起動し直さずにブラウザだけ開く
- `stop` はデータを消すオプション（`-v` など）を持たない。理由：誤操作でモデル数十GBや履歴を消さないため

### 8.5 リセットスクリプト
- **[決定]** 強制終了などで不調になったときに、このアプリを初回起動前と同じ状態に戻す `scripts/reset.sh`（Windows 用に `LocalLLM-reset.bat`）を用意する
- **[決定]** このアプリが作ったものを全部消す（「ガッツリ」リセット）。目的：このアプリが原因で Windows・Ubuntu の動作に影響が残らないようにするため

| 消すもの | 中身 |
|---|---|
| コンテナ | `ollama` / `frontend` コンテナ（止まらないものは強制停止） |
| Docker のデータ | このアプリの volume（ダウンロード済みモデル）、ネットワーク、`frontend` のイメージ、専用ビルダー `local-llm-chat`（ビルドキャッシュごと） |
| 途中生成物 | 中断したダウンロードの残り、ダウンロード中の印、モデル検索の保存結果、このアプリが作った一時ファイル |
| セッション履歴 | `./data/sessions/` の中身（会話と添付画像） |

Claude の判断（修正可）：
- 実行前に消すものの一覧と合計サイズを表示し、`RESET` と入力したときだけ実行する
- 消さないもの：Docker Engine・NVIDIA Container Toolkit 本体、ほかのプロジェクトのコンテナやイメージ、WSL の `/tmp` 全体、`.env` と `models.yaml`（設定は残す）、ソースコード
- Ollama の公式イメージは消さない（ほかで使っている可能性があるため）。消したい場合だけ `--with-images` で消す
- 実行後に「消えたもの」と「次は `start` で初回と同じように起動できます」を表示する

## 9. 完成確認の方法

1. WSL 内から `curl http://localhost:3000` で応答を確認
2. WSL から Windows 側の `curl.exe` を呼び出し、Windows からも届くことを確認
3. Windows のブラウザで `http://localhost:3000` を開き、以下を目視確認
   - デフォルトモデル（`gemma4:e4b`）でチャットできる
   - 未ダウンロードモデルのダウンロード（進捗表示・中止）
   - モデル削除（確認ダイアログ・デフォルトモデルへの切り替え）
   - ブラウザを閉じて開き直しても履歴が残る
   - 画像を添付して、その内容について回答が返る
4. 起動・終了の確認：Windows で `LocalLLM-start.bat` をダブルクリックしてブラウザが開き、`LocalLLM-stop.bat` で止まり、再度 `LocalLLM-start.bat` で履歴とモデルが残っていることを確認
5. リセットの確認：`LocalLLM-reset.bat` 実行後、このアプリのコンテナ・volume・履歴が消え、`LocalLLM-start.bat` で初回と同じくデフォルトモデルのダウンロードから始まることを確認
6. 高負荷の確認：メモリ上限を一時的に小さくして重いモデルを動かし、Ollama コンテナだけが停止・自動復帰し、Windows・Ubuntu・画面が操作できることを確認

## 10. 技術選定

### 検討した案

| 案 | 構成 | 良い点 | 弱い点 |
|---|---|---|---|
| **A Next.js（採用）** | TypeScript 1 言語で、画面とサーバー処理を 1 コンテナに | 画面の状態管理が得意。ストリーミング表示の実例が多い。ComfyUI 連携の画面も足しやすい | 最初の構築ファイルが多め |
| B FastAPI＋素の HTML/JS | Python のサーバー＋シンプルな画面 | 構成が小さい | 状態が増えると画面側の JS が散らかりやすい |
| C 既存の Open WebUI | 完成品を Ollama につなぐだけ | すぐ動く | 「10 件まで保存」「負荷区分で除外」など今回の仕様に合わせた改造が難しい |

- **[決定]** A の Next.js を採用。理由：今回の画面は状態の組み合わせ（ダウンロード中の操作禁止、モデルのロック、ダイアログ、進捗バー、閲覧のみ表示）が多く、それを素直に扱える道具を選ぶのが手戻りが最も少ないため
- **[決定]** `frontend` コンテナの中で、画面と API（Next.js の Route Handlers）を両方動かす

## 11. 実装上の細かい判断（Claude の判断。修正可）

第三者チェックで出た質問のうち、実装者側で決めてよいものを以下のとおり決めた。

1. **応答の打ち切り時間**：「最後に文字が届いてから次の文字が来るまで」の無応答時間で測る（最初の 1 文字までも含む）。応答全体の時間では切らない。理由：低速モデルの長い正常な回答を途中で切らないため
2. **環境構築**：Docker Engine と NVIDIA Container Toolkit の導入手順（スクリプト＋確認コマンド）を実装計画の最初のステップに含める。WSL 内の `nvidia-smi` は動作確認済み
3. **ディスク空き容量の判定**：WSL 内（Ollama のモデル保存先）の空き容量で判定する。補足：WSL の仮想ディスクは Windows の C: ドライブ上で伸びるため、C: の空き（現在約 456GB）が実際の上限になる。C: の空きはアプリでは確認しない
4. **`models.yaml` に無いモデル**：ターミナルで手動ダウンロードしたものも一覧に出す。負荷区分は Ollama が返す実サイズで判定する
5. **起動時のデフォルトモデル自動ダウンロード**：6.2 と同じ進捗ダイアログ・操作禁止の対象にする。失敗した場合はエラーを表示し、他のダウンロード済みモデルがあればそれで使えるようにする
6. **「最新 10 件」の数え方**：最終更新日時で数える。古いセッションを開いて続けると一覧の先頭に上がる。表示中のセッションは自動削除の対象にしない
7. **[停止] や強制終了で途中までになった応答**：途中までの応答を履歴に残し「（中断）」と表示する。未回答の質問も残す。自動の再送機能は作らない
8. **アプリを開いた直後の画面**：新しいチャット（空）とデフォルトモデルを表示する。過去のセッションは左の一覧から開く
9. **会話中のモデルを削除したとき**：デフォルトモデルに切り替え、新しいチャットにする（削除したモデルの会話は一覧に残り、閲覧のみになる）
10. **画像だけを送ったセッションの名前**：「画像の質問」とする
11. **Ollama の同時読み込み**：モデルは同時に 1 つだけメモリに載せ、並列処理もしない（`OLLAMA_MAX_LOADED_MODELS=1`、`OLLAMA_NUM_PARALLEL=1`）。理由：利用者は 1 人で、複数載せるとメモリ上限に当たりやすくなるため
